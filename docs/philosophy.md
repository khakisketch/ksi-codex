# KSI Codex Philosophy

KSI Codex is a goal/plan-driven pragmatic Codex harness.

It is built for:
- AI coding power users
- non-developer founders who build through product screens and AI agents
- individual developers who want disciplined but lightweight agent workflows

## Core Beliefs

1. Keep the harness small.
2. Use `/goal` for work boundaries.
3. Use `/plan` for implementation design and verification before edits.
4. Use `.ai/` only when boundary, handoff, or recovery matters.
5. Use skills for repeated process, not decorative prompt packs.
6. Use plugins and MCP for external development systems, not generic planning loops.
7. Use repo-owned tests for durable regression protection.
8. Use screenshots/browser evidence for UI/UX judgment.
9. Avoid autonomous loops, auto-commit, auto-push, and tool stacks that create developer fatigue.

## What This Is Not

KSI Codex is not:
- an autonomous software factory
- a swarm of role-playing agents
- a replacement for repo tests
- a plugin pack for every SaaS tool
- a workflow that forces planning overhead on tiny edits

## Product Development Focus

KSI Codex treats UI/UX as first-class because many users build by looking at screens, flows, and customer outcomes rather than by reading source code first.

This makes the harness useful for both developers and founders:
- developers can turn screen findings into durable tests and implementation plans
- founders can ask for product improvements in natural language and screenshots
